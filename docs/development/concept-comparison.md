# Concept comparison and Checkpoint 3

Three directions were prototyped against the same snapshots (`fixtures/observations/demo-t*`):

| Direction | Prototype | Form |
|---|---|---|
| 1. Project Radar | [`prototypes/radar/`](../../prototypes/radar/) (`demo-t0…t3.html`) | Polar topology: lanes are sectors, areas are marks, distance from the centre is recency, rings are overlaps, plus signal list with evidence |
| 2. Timeline / Playback | [`prototypes/timeline/`](../../prototypes/timeline/) (`index.html`, `timeline.json`) | Areas × moments grid plus a state-transition log (appeared / resolved / promoted) |
| 3. Agent Coordination Surface | [`prototypes/agent-surface/`](../../prototypes/agent-surface/) (`examples/*.json`, `mcp-tools.json`) | Five queries, each returning a uniform JSON envelope with evidence |

## Evaluation

The table isn't scored on purpose. Each cell is a judgement with a reason.

| Criterion | Radar | Timeline | Agent surface |
|---|---|---|---|
| **Useful in < 10 s** | Strong. The readout row and the accent ring answer "is anything colliding?" at a glance. The overlap signal opens by default | Weak for "now", strong for "how did we get here?" | n/a for humans. For agents a single call answers the pre-flight question |
| **Explainability** | Good. Every mark has a tooltip and every signal opens to its rule and parameters. The radar geometry (distance = recency) needs the one-line legend | Very good. Events are plain sentences | Very good. `basis`, `confidence`, `rule` and `evidence_note` are in every response |
| **Evidence traceability** | Every work item and signal links to GitHub | Refers to signal and work-item ids; links only via the snapshot | URLs in every work item and evidence entry |
| **Cognitive load** | Moderate. The polar layout is novel; the list underneath is the fallback | Low per row, but grows linearly with areas × moments | Zero for humans. For agents, structured and small (only the matching slice) |
| **Install friction** | None: generated by the Action | **High**: needs persisted snapshot history. The Action is stateless (R7). Needs artifact chaining or a hosted store | None: the CLI ships with the Action; an agent can read the uploaded snapshot |
| **PM burden** | None | None | None |
| **Agent usefulness** | Low (HTML) — the embedded JSON helps a little | Medium (`changes_since` is a special case of a diff) | High: this is its purpose |
| **Privacy** | Shows author names on work items (needed for "who do I talk to?"). No per-person aggregates | Same | Same. There is deliberately no per-person query |
| **Works without maintenance** | Yes | Yes, once history exists | Yes |
| **Feasibility in v1** | Done | The prototype is done; production needs storage | Done (CLI); MCP adapter is thin, later |

## Tradeoffs

- **Radar vs. a plain list.** The radar adds a spatial "where" that a list lacks, especially on repos
  with 10–40 areas. It costs novelty, and it reads badly with only 1–2 areas. Mitigation: the
  signal list sits beside the radar and is the primary reading path. The radar is the
  orientation layer. If user testing shows the radar isn't used, deleting it removes one
  function and no state.
- **Timeline is the most convincing *story* but the least installable.** The demo shows
  overlap emerging and resolving, which is exactly the value proposition. But the Action has no
  memory. Two cheap options exist (download the previous run's artifact, or commit snapshots to
  an orphan branch); both push state management into the user's repo, which the architecture
  deferred to the hosted service (ADR-002). Decision: **timeline is v2**, and its diff logic
  (`prototypes/timeline/build.py::diff`) is the spec for the hosted service's event log.
- **The agent surface isn't a separate product.** It is the same snapshot queried differently.
  Shipping it in v1 is cheap and directly proves principle 5.

## Checkpoint 3: selected direction

**Ship Radar (human) + Agent Surface (machine) as two projections of one snapshot. Defer Timeline
to v2, when durable history exists.**

The tradeoff we accept: v1 can't show "how we got here" (P6 in the opportunity map, rank 6).
We take that in exchange for zero-infrastructure install and a demo that proves the top two
problems (P1 overlap, P2 open loops) plus the agent problem (P4). The timeline prototype stays
in the repo as the documented target for v2. See ADR-013 and ADR-014.
