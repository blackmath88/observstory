## Reproduced and fixed

UI replay reduced the entire repository ingestion log. After a force-push or divergent branch, a record created only on the abandoned branch remained in replay even though `state_at` correctly excluded it. The new synthetic regression constructs a shared base and two divergent heads, retains both in memory, and compares the final replay frame with the revision query. It fails before the fix. Replay now filters each event prefix by that event snapshot's ancestry.

Validation: 155 Python tests pass, including the new regression (previous implementation: 154). No provider calls, host installation, or deployment.

## Remaining review findings

- Historical record inspector reads all versions/events and current proposals; a record absent at the selected historical point can fall back to its latest version. This needs an explicit separate all-history mode or temporal filtering before claiming strict historical isolation throughout the UI.
- `ui_bundle.relation_versions` is keyed by logical relation ID, so later relation evidence can replace the earlier evidence shown in historical frames. Preserve relation-version identity in graph projections.
- Live refresh silently retains old data on HTTP/network failure. The user should see a failed-refresh indicator.
- The new TanStack dashboard (af5b2d7) has Overview and Data sources routes; it does not integrate this memory Graph/History/Context application yet.

## Handoff

Finding: deterministic revision queries and graph replay were inconsistent after divergence. Fixed here; acceptance is not implied.
Proposal: repair historical inspector and relation provenance next, then connect the memory views to the dashboard with an explicit runtime/source boundary.
Open question: which reachable host should supply the durable memory page? A static Git reconstruction cannot establish actual past ingestion times.
